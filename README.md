# rag-assistant · 我的私人知识库问答助手

> 一句话：把我约 130 个 Markdown 文档变成「可以提问、并且能指出答案出自哪一段」的问答系统。

## 1. 这是什么 / 解决什么问题

我用 AI 自学，怕它忘记上下文，就把每天的记录和结论写进 Markdown。时间一长，这些文件越积越多——现在 `py_road` 里**约 130 个 Markdown、约 84 万字**（随时增长，精确数见 `eval/成绩单`）。

在这个体量里找一个具体数字，比如"项目三号切块切到了多少块"，我得去 PyCharm 里全局搜索，还得自己判断哪个是旧版本（有一次就翻到了 `_backup` 里的旧副本）。很麻烦。

所以我做了这个助手：直接问它，它把答案告诉我，**并且带出处**——错了能自己核实来源。

RAG 也是我目标方向上很基础的一块，所以我想自己把它研究透、搞懂。

另外我做了个对照实验：不给材料 / 随机给三块 / 按相关性给三块，用来测它靠不靠谱、短板在哪，方便后面改进。结果在第 6 节。

## 2. 怎么跑起来

需要 Python 3.8+。

**1. 装依赖**
```
pip install requests
```

**2. 设环境变量**（Windows）
```
setx ZHIPU_API_KEY "此处填智谱 AI 的 API Key"
```
设完**必须重开终端或 PyCharm** 才生效（环境变量是进程启动时读入的）。

**3. 运行**
```
python 问答.py
```

跑通后应该看到：先出现「载入块数: 47xx」，然后是「材料 top-3」和「答案」两段。

## 3. 项目结构

- **项目三号.py**：切块器。扫约 130 个 `.md`，每个文件切成 300 字一块、相邻块重叠 50 字，每块记录 `file` / `idx` / `start` 三个字段，共**约 3400 块**。
- **检索.py**：把问题切成两字碎片，扔掉问句套话，按 IDF 给每个碎片算权重（某个词在越少的块里出现、权重越高）；遍算所有块，命中碎片的权重相加得分，排序后取前 3 块。
- **问答.py**：把 3 块材料带 `[1][2][3]` 编号拼成一段，加上三条规则（只依据材料、标出处、没有就说没有），调智谱接口取回答案。
- **评测.py**：读 20 道题，逐题跑「检索 + 问答」，输出「系统答案 / 标准要点 / 出处」对照表，供人判定后统计三个数（答对 / 出处对 / 拒答对）。
- **api.py**：最早的原型，验证能不能调通智谱接口，含分层错误处理（超时 / 连接失败 / HTTP 状态码 / 响应结构 / 兜底）。
- **材料实验.py**：同一问题问两次——一次不给材料、一次给材料，用来证明「不给材料模型只会说不知道，给了才答得准」。

## 4. 关键取舍

- **块长定 300 字**，因为要保证一块能装下一个完整论题；代价是每 300 字切一刀，正好落在句子中间时就会割裂——检索到后一块时，主语可能还留在前一块里。
- **相邻块重叠 50 字**，用来缓解块边界切断带来的信息丢失，让单块能看到完整上下文；代价是步长从 300 缩到 250，**块数增加约 20%**（不重叠约 2800 块 → 重叠后约 3400 块），存储和打分都变多。重叠不会吞字，它只是让相邻块重复一段。
- **出处用相对路径而不是文件名**，因为同名文件可能在不同目录，只留文件名会撞车（改之前实测 555 条重复）；代价是出处字符串变长、换根目录或部署到服务器后路径会变（仍然是唯一的，只是不再稳定），还会暴露内部目录名。

## 5. 已知问题

- **2-gram 检索有天花板**：泛动词问题（如"记账怎么用"）检索不到目标文档；一半碎片是跨词的垃圾（如把"三号切块"切成 `号切`），权重高但永远不命中。
- **出处编号会编**：材料只有 3 块，模型输出过 `[编号：6]`。prompt 的约束不够，需要代码校验兜底。
- **引用格式不受控**：出现过 `[编号2]`、`[编号：[3]]`、`[材料里没有]` 三种格式，无法自动校验出处。
- **索引每次重建**：每次启动重扫约 130 个文件、约 3 秒；文档一改，块号就跟着漂移。
- **单文件失败会崩**：130 个文件里只要有一个编码异常，整个索引建不起来。
- **只有 2-gram，没有语义**：问法和文档用词不一致时（"花了多少钱" vs "支出统计"）完全匹配不上。

## 6. 评测结果

自建 20 题评测集（12 道答案在单份文档里 / 4 道需跨 2~3 份文档拼 / 4 道文档里没有，考它会不会编）。同一批题，三种喂法对比：

| 喂法 | 答对 |
|---|---|
| **不给材料**（纯靠模型训练记忆） | **4/20** |
| **随机取 3 块**（不按相关性） | **4/20** |
| **按相关性取 3 块**（本项目的检索） | **16/20** |

- **4 道应拒答题全对**：材料里没有的内容，模型全部回答"材料里没有"，没有编造。
- **3 道应答题答错的原因不是"不会答"，而是"没被检索到"**（答案在库里，但没进 top-3）。
- 随机 3 块那一组里还出现过一次"串味"：它把随机材料里的"字节校招"错当成了结论。

**结论：关键不是"给材料"，是"给对材料"。这也是后续优化的方向——瓶颈在检索，不在模型。**
