# 项目三号 · RAG 小助手 —— 项目说明

> **用途**：讲稿骨架（3 分钟版）＋ 模块划分理由。**README 由学生本人撰写，本文件不替代 README。**

## 一、核心问题

私人知识库有 **179 个 `.md`、约 16.8 万字**（`py_road`）。大模型既不知道这些内容，也读不完（上下文装不下、成本高）。直接问模型，它只能凭训练记忆编。

**要解决的问题**：让模型**基于这些文档回答**，并且**说清依据出自哪一段**。

## 二、问题拆成的五个板块

| 板块 | 文件 | 解决什么 | 状态 |
|---|---|---|---|
| ① 切块 | `项目三号.py` | 文档太长读不完 → 切成 300 字一块，每块带出处（`file` / `idx` / `start`） | ✅ 179 文件 / 约 4749 块 |
| ② 模型调用 | `api.py` | 文字变人话 → HTTP 调模型；超时／网络／鉴权／限流／参数错各有明确提示 | ✅ 三种情况实测通过 |
| ③ 材料实验 | `材料实验.py` | 证明"为什么必须给材料" → 同一问题问两次对比 | ✅ 已验证 |
| ④ 检索 | `检索.py` | 4749 块里只能塞 3 块 → 打分、排序、取 top-3、去重 | 🟡 能跑；具体名词问题命中，泛动词问题不命中 |
| ⑤ 评测 | 未建 | "好不好"不能靠感觉 → 20 题、三个数字 | ⬜ 未开始 |

**一句话对应**：切块解决"太散"，检索解决"太多"，模型解决"变人话"，评测解决"怎么知道好不好"。

## 三、整体流程（三条链）

**链 A · 建索引（离线，跑一次，约 3 秒）**
```
os.walk 扫 179 个 .md（排除 .git / __pycache__ / .venv / _backup / _drafts）
  → 逐文件 f.read() 成整篇「文本」
  → range(0, len(文本), 250) 逐起点切片，每次取 300 字
  → 存 {file: 相对路径, idx: 第几块, start: 原文位置, text: 正文}
  → 全部块（约 4749 项的列表）＝ 索引
```

**链 B · 问答（每次提问）**
```
问题 → 检索打分 → 排序取 top-3 → 拼 messages（system 定规则 + user 材料与问题）
     → api.py 发 HTTP → 模型 → 返回「答案 + 出处」
```

**链 C · 评测（离线，定期）**
```
20 题（12 应答题 / 4 跨文件 / 4 应拒答）→ 逐题跑链 B → 人工对比标准答案
→ 三个数：答对 N/20、出处对 N/16、拒答 N'/4
```

## 四、板块调用关系

```
材料实验.py  ← 独立（验证"给不给材料"，不进主链）

检索.py
 ├─ importlib 加载 → 项目三号.py   取 全部块
 └─ （待接）       → api.py 的 问()  取答案

评测脚本（未建）
 └─ 调 检索 + 问 → 产出三个数
```

**关键依赖**：`检索.py` 不自己扫盘切块，而是加载 `项目三号.py` 取现成的 `全部块`——**切块规则只有一处定义，改一处两边都变**。

## 五、已知问题（不藏）

1. **2-gram 检索有天花板**：具体名词问题（"三号切块块长"）能命中；泛动词问题（"记账怎么用"）命中不到目标文档。原因是"记账"出现在 283 个块里、且 2-gram 不懂语义。升级路径见 `py_road\项目迭代清单.md` I2（embedding 对照实验）。
2. **归一化会引入"短块占优"**：实测改为 IDF 加权后解决。
3. **`file` 用相对路径**：更唯一，但出处变长、跨环境需固定根目录。
